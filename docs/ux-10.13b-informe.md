# 10.13B — Consistencia visual y notificaciones

Fecha: 24 de octubre de 2026

## Alcance

Se implementó la fase 10.13B sobre el frontend `prototipo-titulacion`, tomando como referencia [la auditoría 10.13A](./ux-10.13a-auditoria-informe.md). No se modificaron cálculos, evaluaciones, actas, contratos API, migraciones ni datos de demostración.

## Cambios realizados

### UX-01 — Notificaciones

- La campana y el panel de notificaciones locales solo se montan cuando todas las fuentes operativas están en modo prototipo.
- Cuando `npm run dev` activa cualquiera de las fuentes API (trabajos, evaluaciones, programaciones o rúbricas), la campana queda oculta; no se presentan notificaciones ficticias ni se simula una API inexistente.
- `npm run dev:web` conserva el centro de notificaciones local y sus datos de demostración.

### Consistencia visual y textual

- Se mantuvo el uso de `AlertaInstitucional`, `InsigniaEstado`, `EncabezadoPagina` y los botones compartidos como superficies comunes para avisos, encabezados, estados y acciones.
- Se reforzaron los estilos compartidos de avisos institucionales y diálogos: separación, radios, tipografía, cierre de contenido y espaciado de acciones.
- Una evaluación cerrada ya no muestra simultáneamente «Escritura autorizada» y «Solo lectura»; el encabezado presenta únicamente el estado efectivo.
- Se normalizaron tildes visibles en la pantalla API de evaluaciones: «Gestión académica», «aparecerán aquí», «rúbrica», «asignación» y «evaluación».

### UX-06 — Cambios sin guardar

- Se eliminó el uso de `window.confirm` para cancelar o volver desde formularios con cambios.
- Las rutas de retorno y cancelación usan el diálogo `DialogoGenares`, con botones «Descartar cambios» y «Seguir editando», confirmación explícita y retorno de foco gestionado por SweetAlert2.
- La protección `beforeunload` se conserva para salidas del navegador, donde el agente de usuario exige su diálogo nativo.
- Al confirmar el descarte se limpian los registros activos y se ejecutan sus restauradores antes de navegar.

## Separación de modos

La configuración existente de `scripts/dev.mjs` se conserva:

- `npm run dev`: inicia el frontend con fuentes API, proxy a NestJS y PostgreSQL local en `127.0.0.1:55442`.
- `npm run dev:web`: inicia únicamente Vite con fuentes prototipo, sin backend ni base de datos; sus formularios pueden persistir en el `localStorage` propio de la demostración.

Ambos comandos llegaron a la fase de arranque y mostraron sus mensajes de modo. No fue posible iniciar una segunda instancia durante esta validación porque el puerto 5173 ya estaba ocupado por un entorno existente; no se detuvieron procesos ajenos. La revisión del lanzador confirma que los modos usan fuentes y procesos separados. No se accedió a 8E ni se realizaron conexiones a 5432.
