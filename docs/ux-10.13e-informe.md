# Informe UX 10.13E — Auditoría final y estabilización UX

Fecha: 24 de octubre de 2026

## Alcance y restricciones

Se revisaron los informes 10.13A–10.13D y el frontend `prototipo-titulacion`. La corrección implementada fue únicamente de UX: se eliminó la propagación del ancho mínimo de la tabla del Cronograma hacia el grid de la página. No se modificaron reglas académicas, notas, evaluaciones, actas, contratos API, migraciones ni datos persistidos.

No se accedió a 8E ni al puerto 5432. PostgreSQL 10.9B se consultó mediante el entorno integrado ya disponible, sin escrituras ni migraciones. No fue necesario utilizar 9D.

## Hallazgo y corrección

### UX-02 — Desbordamiento horizontal global del Cronograma

**Reproducido antes de la corrección:** el wrapper de la tabla tenía desplazamiento horizontal local, pero el ancho mínimo de la tabla se propagaba al grid padre. En 1024 px el documento alcanzaba 1420 px y en 390 px alcanzaba 1392 px.

**Corrección:** `cronograma-page` usa una pista `minmax(0, 1fr)` y `cronograma-screen-only` tiene `min-width: 0` y `max-width: 100%`. La tabla mantiene su ancho mínimo dentro de `cronograma-table-wrap`, por lo que conserva legibilidad sin ensanchar el documento.

Con una programación API cargada, se midió el ancho global y el wrapper de tabla:

| Viewport | Ancho del documento | Ancho visible del wrapper | Ancho interno de tabla | Resultado |
|---|---:|---:|---:|---|
| 1440 | 1425 | 1022 | 1333 | Sin overflow global; scroll local |
| 1024 | 1009 | 902 | 1333 | Sin overflow global; scroll local |

La región «Tabla de sustentaciones programadas» tiene nombre accesible, `caption`, foco por teclado y conserva el desplazamiento horizontal interno. El foco visible global se comprobó en el enlace de apertura del PDF; el estilo específico de la región se conserva para navegación de teclado.

## Separación de modos

La inspección de `scripts/dev.mjs` confirma:

- `npm run dev`: fuentes API, proxy NestJS y PostgreSQL local en `127.0.0.1:55442`.
- `npm run dev:web`: solo Vite con fuentes de prototipo, sin backend ni base de datos.
- Las fuentes API se configuran como `api` en el modo integrado y como `prototipo` o deshabilitadas en el modo frontend-only.

No se iniciaron ambos comandos en paralelo porque el entorno compartido ya tenía ocupado el puerto 5173; esta limitación se mantiene para la validación operativa de arranque.
