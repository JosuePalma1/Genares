# Informe UX 10.13D — Tablas, formularios y documentos

## Alcance

Se implementaron ajustes exclusivamente de presentación, responsive y accesibilidad en el frontend `prototipo-titulacion`. No se modificaron cálculos, notas, evaluaciones, actas, contratos API, migraciones ni datos persistidos.

## Cambios realizados

### UX-02 — Cronograma y tablas anchas

- El Cronograma conserva una tabla con ancho mínimo para mantener la legibilidad de sus ocho columnas, pero el desplazamiento horizontal queda confinado en `.cronograma-table-wrap`.
- El contenedor tiene `min-width: 0`, `max-width: 100%`, desplazamiento horizontal accesible mediante teclado (`tabIndex="0"`), `role="region"` y un nombre accesible.
- Se añadió un `caption` no visible para identificar la tabla a lectores de pantalla.
- Se reforzaron los límites de ancho del contenido principal y de la cabecera para evitar que la tabla o sus acciones provoquen desbordamiento de la página.
- Las actas archivadas de Documentos usan el mismo patrón: región desplazable propia, foco visible, caption, encabezados con `scope` y ancho mínimo legible.

### Tablas, filtros, contadores y acciones

- Se conservaron los componentes y clases de botones, avisos y tablas existentes.
- Los filtros del Cronograma mantienen una cuadrícula de cuatro columnas en escritorio, dos en tablet y una en móvil.
- Los botones de acción de documentos pasan a disposición vertical y ancho completo en pantallas pequeñas.

### Formularios y editor de rúbricas

- Se mantuvieron los grids existentes del editor estructural de rúbricas y sus handlers.
- Los breakpoints existentes llevan etapas, categorías, indicadores, campos y acciones a una columna cuando el espacio es reducido.
- Se reforzó `min-width: 0` en el contenido principal para que esos grids puedan encogerse sin recortar campos ni crear overflow global.
- El foco visible global existente se conserva para controles, enlaces, regiones desplazables e inputs.

### UX-05 — PDF original del servidor

- Se conserva el iframe actual para visualizar el documento.
- Se añadió la acción explícita **«Abrir PDF en pestaña nueva»**, con `target="_blank"` y `rel="noreferrer"`, usando la misma URL PDF entregada por el servidor.
- El iframe mantiene una altura adaptable (`75vh`, con mínimo) y una altura menor en móvil para permitir vista ampliada sin eliminar el visor.

## Verificación

- Suite frontend: `npm run test` desde `prototipo-titulacion` — aprobada.
- Build: `npm run build` desde `prototipo-titulacion` — aprobado con Vite.
- Formato: `git diff --check` — aprobado; Git solo mostró advertencias informativas de conversión LF/CRLF.
- Navegador: se verificó el Cronograma con datos API cargados. La región accesible se anuncia como **«Tabla de sustentaciones programadas»**, la tabla incluye caption, y las acciones de fila permanecen disponibles.
- Se inspeccionó el resultado API existente en navegador con datos cargados, incluyendo textos de resultado consultivo, escala sobre 10.00 y ámbitos de etapa.
- Se intentó cambiar el viewport automatizado a 1440, 1024 y 390 px. El navegador compartido mantuvo una métrica de viewport inconsistente durante la emulación, por lo que no se certifica una medición visual pixel-perfect de esos tres tamaños. El CSS incluye breakpoints explícitos para `900/620 px`, límites de ancho y desplazamiento local; se recomienda repetir la comprobación manual en DevTools si se requiere evidencia visual adicional.
